## F3: HTML round-trip, decision (2026-09-10)

Corpus: 224 HTML fields from 200 recent CloudCover 2.0 items (92 with tables, 71 with images, 40 nested lists, 13 mentions). Delta-based editors fail the corpus: Quill (`flutter_quill_delta_from_html` → `vsc_quill_delta_to_html`) and Fleather (`parchment` HTML codec) lost the table in 8/8 real samples and the `data-vss-mention` attribute in 6/6; Quill also folded everything after a mention into one `<pre>` on the synthetic fixture. ## F4: Kanban drag-and-drop, decision (2026-09-10)

Profile build on the Pixel 10 Pro emulator, 200 generated cards in 5 columns, the same adb gesture battery (`research/spikes/f4_drive.sh`) for every candidate, frames from `SchedulerBinding.addTimingsCallback`. Drag-window jank (UI or raster thread over 16.7 ms): hand-rolled `LongPressDraggable` + `DragTarget` 2.1% (raster p90 9.6 ms), `boardview` 1.0.0 15.5% (rebuilds the whole board per pointer move), `drag_and_drop_lists` 0.4.2 24.7% (raster p90 17.7 ms, no usable horizontal edge scroll), `appflowy_board` 0.1.2 no drag hooks at all, eager layout of every card (83 ms first build), own model to mirror, last release 2024-04. `super_drag_and_drop` was not built: it needs a Rust toolchain on every machine. At 1,000 cards the hand-rolled drag window stayed at 2.1%. **Decision: no package; Flutter's own drag primitives with a hand-rolled column layout.** Production notes: own the drag session in a `Listener` around the board, because a `Draggable` that auto-scroll unmounts (lazy list) never reports drag end while its drop still lands; key card slots by id; render the source placeholder from board state rather than `childWhenDragging` if columns stay lazy, or keep columns alive for the usual 5–8; snap horizontal auto-scroll per column and cap its speed; haptics on lift, slot change and drop. Details: `f4-kanban-dnd.md` (gitignored). Probe: Diagnostics → Board probe.
