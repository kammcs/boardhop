## Smaller observations

- This PAT reaches work, code, wiki, search, service hooks, favorites and teams, and is denied on build, pipelines, release, Graph, identities, notification subscriptions, extension management and entitlements. A read-only PAT for future spikes should add `vso.build`, `vso.graph`, `vso.notification`, `vso.profile` and `vso.extension`.
- `GET {org}/_apis/teams?$mine=true` at `7.1-preview.3` works and returned three teams across the org in one call.
- `wit/workitems` accepts `7.1`, `7.2-preview.2` and `7.2-preview.3`; `7.2-preview.4` returns a clean `VssVersionOutOfRangeException` (400).
- Work item 15433's description contains entity-escaped HTML (`&lt;p&gt;…`), presumably written through an integration. The renderer must not crash on escaped markup and should probably show it as text.
- Test Case work items carry no board fields; the board query must filter to the backlog's work item types.
- `canEdit` was `false` on the Stories board for this user, so board configuration writes must be gated on it.
- The "CloudCover 2.0" process is a customised Agile process: ten User Story states, custom types (Tech Task, QA Task, Bug Task), and custom fields (`Custom.QAStoryPoints`, `Custom.QAAssignee`). A good stress test for dynamic forms.

## F1: msal_auth sign-in on Android (2026-09-10)

Pixel 10 Pro emulator, Android 17, no Authenticator (browser fallback). Interactive sign-in through a Chrome custom tab succeeded; after `am force-stop` the app restored the session silently. Access token 2,051 bytes, 75-minute lifetime, issued for the puremedia tenant with ten `vso.*` scopes from `.default`. `app.vssps` `profiles/me` and `accounts?memberId` worked with the Entra token (one org), `dev.azure.com/puremedia/_apis/projects` returned four projects, and the org-scoped `vssps` profile matched. `X-RateLimit-Cost` 0.0036 on the projects call. Emulator needed `-dns-server 8.8.8.8,1.1.1.1` on this host. Raw report: `f1-device-run.md` (gitignored).

## F2: claims challenge through msal_auth (2026-09-10)

`msal_auth` 3.5.3 has no `claims`/`forceRefresh` parameters, so the plugin is vendored at `packages/msal_auth` with those added on Dart, Android and iOS, plus `clientCapabilities` for Apple (Android takes `client_capabilities` from the config JSON). On the emulator, `forceRefresh` returned a new token after a network round trip, and a claims request was accepted by the token endpoint, so the plumbing to native MSAL works. `AdoClient` retries a 401 once through `AuthService.resolveChallenge` (silent with claims → interactive with claims). With CP1 declared the token grew by about 110 bytes but its lifetime stayed at 70–85 minutes, not the multi-hour CAE lifetime. Untested: a real revocation event and the iOS build of the Swift patch. Raw report: `f2-claims-challenge.md` (gitignored).

## F3: HTML round-trip, decision (2026-09-10)

Corpus: 224 HTML fields from 200 recent CloudCover 2.0 items (92 with tables, 71 with images, 40 nested lists, 13 mentions). Delta-based editors fail the corpus: Quill (`flutter_quill_delta_from_html` → `vsc_quill_delta_to_html`) and Fleather (`parchment` HTML codec) lost the table in 8/8 real samples and the `data-vss-mention` attribute in 6/6; Quill also folded everything after a mention into one `<pre>` on the synthetic fixture. AppFlowy 6.2.0 does not compile on Flutter 3.47. The HTML-native `html_editor_enhanced` round-tripped the synthetic fixture (18/18 constructs, 97% text) and a live 13 KB ReproSteps field (10/10 constructs, 100% text) on the emulator. **Decision: `html_editor_enhanced` for editing; `flutter_widget_from_html_core` for read views.** Caveats: needs the `flutter_inappwebview` 6.2 betas on AGP 9; set content via `evaluateJavascript` + `jsonEncode`, not the plugin's `setText`; keep the editor widget's slot stable; attachment images need an auth header. Details: `f3-delta-editors.md`, `f3-editor-probe.md` (gitignored). Harness: `research/spikes/f3_harness/`.

## F4: Kanban drag-and-drop, decision (2026-09-10)

Profile build on the Pixel 10 Pro emulator, 200 generated cards in 5 columns, the same adb gesture battery (`research/spikes/f4_drive.sh`) for every candidate, frames from `SchedulerBinding.addTimingsCallback`. Drag-window jank (UI or raster thread over 16.7 ms): hand-rolled `LongPressDraggable` + `DragTarget` 2.1% (raster p90 9.6 ms), `boardview` 1.0.0 15.5% (rebuilds the whole board per pointer move), `drag_and_drop_lists` 0.4.2 24.7% (raster p90 17.7 ms, no usable horizontal edge scroll), `appflowy_board` 0.1.2 no drag hooks at all, eager layout of every card (83 ms first build), own model to mirror, last release 2024-04. `super_drag_and_drop` was not built: it needs a Rust toolchain on every machine. At 1,000 cards the hand-rolled drag window stayed at 2.1%. **Decision: no package; Flutter's own drag primitives with a hand-rolled column layout.** Production notes: own the drag session in a `Listener` around the board, because a `Draggable` that auto-scroll unmounts (lazy list) never reports drag end while its drop still lands; key card slots by id; render the source placeholder from board state rather than `childWhenDragging` if columns stay lazy, or keep columns alive for the usual 5–8; snap horizontal auto-scroll per column and cap its speed; haptics on lift, slot change and drop. Details: `f4-kanban-dnd.md` (gitignored). Probe: Diagnostics → Board probe.

## F5: diff viewer prototype, decision (2026-09-10)

Profile build on the emulator, 3,000-line synthetic Dart file with 44 hunks, and a live read of PR 8319. Own Myers line diff (`LineDiff`; `diff_match_patch` 0.4.1 does not export its line mode and has not moved since 2021, so it is used only for the intra-line character emphasis): 1 ms for 3,078 rows. `re_highlight` 0.0.3 whole-file highlighting split into per-line runs so block comments keep their color: 376 ms for both sides of the 3,000-line file, the only cost that must leave the UI thread. `super_sliver_list` 0.4.1 vs `ListView.builder`: jump to line 2,712 in 101 ms landing exactly, against 902 ms with a 750 ms build frame and a 50-line miss (a plain sliver list has to lay out every preceding row to find an offset). Tap-to-comment gutter inserts a composer row in place; long lines pan horizontally under one outer scroll view. Live: PR 8319 iteration 2 through the Items API (`includeContent=true` at `commonRefCommit` and `sourceRefCommit`) with threads read at `$iteration=2&$baseIteration=0`; both spike-w03 threads rendered under their tracked lines (8 and 9) with "moved from line 5/6" from `trackingCriteria`. **Decision: hand-rolled Myers line diff + `re_highlight` + `super_sliver_list`, unified view, custom row widgets.** Production notes: highlight in an isolate or per visible hunk; collapse unchanged runs with an expander row; cache file content by commit/blob SHA; the composer posts a thread with `threadContext` on the right side plus `changeTrackingId`/iteration context (research/01 §PR threads); Markdown-render comment bodies; a split view is a later option since rows already carry both line numbers. Details: `f5-diff-viewer.md` (gitignored). Probe: Diagnostics → Diff probe; battery `research/spikes/f5_drive.sh`.
