# 13. iOS walkthrough plan for the 2026-09-12 features

Everything the Windows session landed between `636fce3` and `f1a399b` was verified on the Android emulators only. This plan checks it on the iPhone 17 and iPad Pro 13" simulators on Kelly's Mac, one agent per device. Section 1 is shared; sections 2 and 3 are the per-device scripts; section 4 is the report format.

## 1. Shared ground rules and setup

**Hard rules (from CLAUDE.md, no exceptions).** Writes go only to the scratch project **"DevOps Mobile App"** in the puremedia organization (CloudCover 2.0, Product, Special Projects and AI are read-only, including favorites, comments, votes, runs). Never print, log or record the Entra client ID, tokens, PATs or anything from `.env`. Do not commit or push; do not change source files. Do not run anything that costs money (no pipeline runs outside `boardhop-scratch`, and none at all unless a step says so).

**Environment.**

- Both simulators are booted and signed in as Kelly (puremedia). The apps are debug builds started with `flutter run` (pid files in the session scratchpad: `iphone.pid`, `ipad.pid`); `kill -USR2 $(cat <pidfile>)` hot-restarts if the app gets stuck, `kill -USR1` hot-reloads. Debug builds show asserts and overflow stripes; treat every red screen or yellow stripe as a finding.
- Driving: `tool/shot-ios.sh <name> [tap X Y | swipe X1 Y1 X2 Y2 MS | text "..." | back | home | wait S]...` with `DEVICE=iphone|ipad`. Coordinates are in the 400-px-wide thumbnail it writes to `.shots/<name>_s.png` (raw frame in `.shots/<name>.png`). In landscape set `ROT=left` (island / status bar on the right) or `ROT=right` (island on the left); the thumbnail then reads normally and taps are taken in that space. **Always look at the screenshot (Read the thumbnail) before tapping**, and screenshot again after: the driver has no assertions. The `back` edge swipe never works; tap the app bar arrow. Bottom-bar taps on the phone must hit the icons (y≈800 in portrait), not the strip below.
- Rotating: `~/.venvs/idb/bin/idb ui rotate --udid <udid> PORTRAIT|LANDSCAPE_LEFT|LANDSCAPE_RIGHT`, which sets an absolute orientation and is deterministic. `LANDSCAPE_RIGHT` puts the Dynamic Island on the **left** (`ROT=right`); `LANDSCAPE_LEFT` puts it on the right (`ROT=left`). The osascript Device > Rotate Left recipe this replaces was not reliable: the first call did nothing (byte-identical frame) and, once the Simulator had been activated, it applied two rotations at once (iPhone run, 2026-09-12). Screenshot afterwards anyway.
- Appearance and type size: `xcrun simctl ui <udid> appearance dark|light`, `xcrun simctl ui <udid> content_size extra-extra-extra-large|medium`. Restore `light` and `medium` when done.
- The simulator camera does not exist; "Take photo" should fail gracefully. The photo library has Apple's sample pictures.
- Long-press drag (board drag-and-drop) cannot be driven through idb; note it as not exercised.
- Keep screenshot names prefixed per device (`ip_…` on the phone, `pad_…` on the iPad) so the two runs do not overwrite each other.

**Test data (scratch project only).** Work items 15503–15507 and 15539–15553 exist from the spikes and phases; team template "Boardhop spike task" (Task); PRs 8334 and 8336; pipeline `boardhop-scratch` (id 139). Create new items with titles starting `[ios-iphone]` or `[ios-ipad]` so the report can list them; do not delete anything.

**What to look for on every screen.** Content clear of the Dynamic Island in landscape (phone), the glass rail full width and clear of the island, no text under the rail, dialogs centered and readable, no overflow stripes, snackbars dismissing, pull-to-refresh working, the page opening from cache then refreshing, dark mode readable, xxxL text not overflowing. Screens the phase notes never saw on iOS are the point of this run: **phase 2's tablet dialog on the iPad**, phase 3's edit form and 412 banner, phase 4's board `+` and drafts, phase 5's Links and Attachments pages and the image picker on iOS.

## 2. iPhone 17 plan (agent "iphone")

Start in **portrait** (rotate as needed; the phone may be in landscape with the island on the left). Portrait is the main pass; section 2.9 repeats key screens in landscape.

1. **Baseline.** Screenshot the current screen. Go to Organizations → puremedia → DevOps Mobile App → Home. Note the four tabs in the bottom bar. Pull to refresh on Home.
2. **Work list and the `+`.** Work tab: the `+` sits left of the Items/Board pill, icon only. Tap it: a **bottom sheet** type chooser, backlog types first (Epic, Feature, User Story…), then a collapsed "Other", "Recent" pinned if any, and under Task the templates row ("Blank", "Boardhop spike task"). Screenshot the sheet expanded.
3. **Create a User Story (phone form).** Pick User Story. Check: full-screen page, pinned header with type chip, Title, State (read-only, colored), Assigned to / Area / Iteration / Tags chips; group cards below in web order (Description, Planning, Classification…); Links and Attachments as sections at the bottom (phase 5), not "Available after creation". Try Save with an empty title (blocked, error under Title). Type title `[ios-iphone] story <time>`, set Priority through the allowed-value sheet, set Assigned to through the people picker (search Kelly's name; "Me" pinned), set Iteration through the tree picker (team iterations first), add a tag. Open Description: the rich editor full screen with the Rich text / Markdown toggle; type a line with bold; Done. Screenshot every picker. Save. Confirm the detail page opens for the new item and the list refreshed with it.
4. **Edit through the form (phase 3).** On the new item tap the pencil: same form in edit mode, full screen. Change the title (append " edited"), move State New → Active through the State chip (transitions only; Reason appears). Save: back on the detail page with "Saved", values updated. Re-open edit, change nothing: Save disabled. Open edit, change something, tap the Work tab in the bottom bar: the unsaved-work prompt (Keep draft / Discard / Cancel style or discard dialog); Cancel back.
5. **Detail page fields (follow-up).** On #15546 or the new item: every field of the layout is rendered in groups; Development and Deployment groups say "Managed in Azure DevOps"; the Links row lists parent/children/related; an Attachments count if any. Pull to refresh. The state sheet from the quick actions lists only legal transitions.
6. **Add child / Add related (phase 4).** From the new story's overflow menu: **Add child** offers Task and Bug; create Task `[ios-iphone] child` — the form shows "Child of #N – title", Area and Iteration copied. Save; the parent's Links row shows Children (1). Then **Add related** on the child, cancel it.
7. **Board `+` (phase 4).** Switch to Board. Each column ends in `+ New item` (a split column in its Doing half only). Tap it in Active: the story form opens with no chooser (Stories board has one type); title `[ios-iphone] board item`; Save. The board reloads and the new card flashes in Active/Doing. Check the lane chips and the WIP count.
8. **Templates and drafts (phase 4).** Work `+` → Task → "Boardhop spike task": the form is pre-filled (title with a trailing space and the caret after it, Priority 1, tags). Change the title to `[ios-iphone] draft test`, then close the form (app bar X / back): Keep draft / Discard / Cancel → Keep draft. Re-open `+`: "Resume draft: Task – [ios-iphone] draft test – just now" with a delete icon. Resume it, Save. Re-open `+`: no draft row.
9. **Links page (phase 5).** Open the child task's edit form, Links section: grouped by kind, rows with title/type/state. Add a Related link through the sheet (search by typing the story's id exactly, and by a title word), Save, read the Links row on the detail page. Then remove it again (× or swipe) and Save.
10. **Attachments page (phase 5) and Insert image.** On the same item, Attachments section: **Take photo** (simulator: expect a graceful message, not a crash), **Choose from library** (pick a sample photo; it uploads at once on an existing item; thumbnail appears with name and size), **Choose file** (the Files app picker: pick anything available or cancel). Open the image full screen (pinch/zoom viewer). Then open Description → rich editor → the **Insert image** toolbar button → library → Done: the image renders on the detail page. Check the Attachments count on the detail page.
11. **Comments and PR threads (findings d/e).** PRs tab (Home → My pull requests or the org inbox) → PR 8334 → **Comments** tab: file threads listed with "file:line" headers, All / Active / Resolved chips with counts. Tap a file thread header: the diff opens at that line with the gutter pinned while the code pans sideways (finding f). Reply on a thread: Cancel + Resolve while empty, Cancel + Reply + "Reply & resolve" with text. Post a reply `[ios-iphone] reply`, then resolve it, then reactivate. Repo-scoped PR list (Repos → the repo → Pull requests) opens on **All active** (finding i).
12. **Pull-to-refresh everywhere (finding a).** No refresh icon anywhere: work item detail, PR detail tabs, PR diff, pipeline log. Pull on each, including a short page.
13. **Home reload (finding c).** Change something (state of the new story on its page), switch to Home: rows refresh when older than two minutes; not a hard check, just note the behaviour.
14. **Reviewer avatars (finding b).** PR 8334 reviewers show photos, not initials, where Graph has them.
15. **Pipelines smoke.** Pipelines tab → runs list, one run page, one log page. No queueing, no cancel.
16. **Dark mode and xxxL.** Dark: the form, the chooser sheet, the board with the `+` row, the Comments tab. xxxL: the phone form header and a picker; look for overflow stripes. Restore light / medium.
17. **Landscape (island left, `ROT=right`).** Rotate. Home with the glass rail on the right at its margin, content clear of the island; the Work list; the phone form as a **dialog** (the window is ≥ 640 dp wide here, so the tablet arrangement may apply: note which); the board sliding under the rail; then rotate 180° (`ROT=left`) once to confirm the rail moves to clear the island. Leave the phone in **portrait** at the end.

## 3. iPad Pro 13" plan (agent "ipad")

1. **Baseline.** Screenshot. Organizations → puremedia → DevOps Mobile App → Home: two-column Home (SideBySide), glass rail on the right at 80% height. Pull to refresh.

## 4. Report

Each agent writes `findings_<device>.md` in the session scratchpad with, per step: **pass / fail / not exercised**, one line of what was seen, the screenshot names that show it, and for a failure the exact symptom (console line from the `flutter run` log if any: `run_iphone3.log` / `run_ipad3.log` in the scratchpad, grep for `EXCEPTION`, `overflowed`, `Error`). End with: the scratch items created (ids and titles), anything written to PR 8334, and a ranked list of defects with a suggested owner file when obvious. Copy the six most telling screenshots (best and worst) to the scratchpad as `<device>_best_N.png` / `<device>_worst_N.png`.
