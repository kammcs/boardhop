## Open item: the grouped view truncated once on the iPad

After the first scope switch of a fresh session (Project → All, software keyboard up), the
grouped view showed **only the Work items section**. The Code and Pull requests sections were
not merely empty — they were absent, with neither their rows, their "Searching…" line nor their
"No results" line, and the list had nothing to scroll to. It survived four screenshots over a
minute and a hot reload, and healed the moment the scope was toggled again. This is the same
artefact S2 saw once on the iPhone.

What was established:

- **Not an exception:** the console has no error over the whole run, and a build failure would
  have drawn a red `ErrorWidget`, not a blank.
- **Not the state:** the slices had their answers — the same query redrawn a second later was
  complete.
- **Not reproducible on demand:** three cold restarts driving the identical path, plus sixteen
  scripted scope toggles, all painted three sections, and every render tree that could be dumped
  in the act had all three sections live. The one dump taken in the broken state could not be
  captured before the page healed.

**Hardening applied, not a proven fix:** every row of the page's `ListView` now carries a key.
The children come and go — the progress bar at the top most of all — and a list whose children
have no keys reuses its elements by position, so the bar appearing re-slots every section under
it. Keys make the reuse follow the section. The truncation has not recurred since, over one more
cold restart and the rest of the iPad pass, but that is not proof.

## Other observations (not fixed)

- A **custom work item type** the icon map does not know (a client project's "Tech Task") draws
  the fallback hollow circle where the built-in types draw their glyph. The row always spells the
  type's name out beside it, and the Search API carries no type definition to read the real icon
  from, so this is cosmetic.
- A pull request row in the All-projects scope reads `<project> / <repository> · !id`, which is
  the PR list's own `showProject` row and repeats itself when a project and its repository share
  a name.
