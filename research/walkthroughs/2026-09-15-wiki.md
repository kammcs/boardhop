## What changed during the walk

### 1. A wiki page whose title carries a percent escape was unreachable

`WikiSearchHit.pagePathOf` turned a git file name back into a page path with
two rules — `-` to a space, `%2D` back to a hyphen — because those are the two
research/20 §1 names. A real page proved there is a third: **every other
character the file name escapes stays escaped**. The row read
`…Meeting%3F` instead of `…Meeting?`, and because the same string is the path
the reader asks for, opening it answered
`Wiki page '…%3F' could not be found`.

`WikiSearchHit.decodeGitName` now replaces `-` with a space and then
percent-decodes the rest in one pass, so `%2D` still becomes a hyphen, `%3F`
becomes a question mark and a multi-byte sequence becomes its own character; a
half-escaped name that Dart will not decode falls back to the old two rules
rather than throwing. `WikiLink._titleFromSlug` follows the same rule for the
id form's title slug. The page opens. Tests in
`test/data/wiki_models_test.dart`.

### 2. A heading's markdown showed in the contents

A real page's heading reads `**_Optional step for after the meeting_**`, and
the in-place `[[_TOC_]]` card and the contents sheet both listed the asterisks
and the underscores. The same raw text was also the anchor, so
`WikiLink.anchorId` kept the underscores and the anchor did not match the one
the wiki gives that heading.

`WikiMarkdown.headingText` now strips the inline markdown before the label and
the anchor are made: a link keeps its label, `**`, `*`, `~~` and backticks
always go, and an underscore goes only at a word boundary so `snake_case` in a
heading keeps its own. Tests in `test/features/wiki_page_view_test.dart`.

### 3. The picker dialog was a tall empty box on the iPad

`showWikiPagePicker` capped itself at three quarters of the screen, which is
right for a phone sheet and 1,032 pt on an iPad — mostly empty box for a wiki
of a dozen pages (`wd80-ipad-picker`). The dialog branch now takes
`min(620, 75 %)`, the same cap the form's own Add link dialog uses
(`wd85-ipad-dialog`).

### 4. The wiki section was third, not fourth

Cosmetic, and caught by reading K4 next to the screen: the section was built
between Code and Pull requests. It is now the last of the four, which is what
research/20 K4 says and what the field's hint now lists.

  pill, the version on every read and the picker's path-form URL with

  exercised on a device.

  TSTU), but a wiki an order of magnitude larger has never been seen.

  (recorded in the dashboards walkthrough); the raw frames are correct and taps
  map correctly.

  registration (research/09), so the app cannot sign in here.
