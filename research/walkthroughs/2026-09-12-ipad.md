Run: 2026-09-12, simulator 929DE352-434C-4CE6-BB96-5C34212741E8, debug build from `flutter run`
(console `run_ipad3.log`). Script: `research/13-ios-walkthrough-plan.md` section 3.
Screenshots in `.shots/pad_*` (thumbnails `_s.png`, taken with `DEVICE=ipad ROT=left`).

`failed` line for the whole run. The only recurring output is html_editor_enhanced noise —
`JavaScript execution returned a result of an unsupported type` plus a Summernote style map,
once per editor keystroke/callback (harmless, but it floods the log).

## Ranked defects

1. **Reviewer avatar on the PR overview is initials, not the Graph photo.** PR 8334 → Reviewers (1)
   shows a grey "KK" circle while the same person's photo loads on the author chip, in the PR list,
   on Home and on board cards. Finding (b) was reported fixed; it is not fixed on this path.
   Owner: the reviewer row in `lib/features/pull_requests/` (the `IdentityRef` built from the PR's
   `reviewers[]`, whose `_links.avatar` fallback appears not to be applied there).
   Screenshot: `ipad_worst_1.png` / `pad_104_pr_wait_s.png`.

2. **The people picker lists Kelly twice** — "Kelly Kamm (Me)" pinned *and* "Kelly Kamm" from the
   team-member list, with the same address, both while browsing and while searching. The phase 2
   review note claims this was de-duplicated.
   Owner: `lib/features/work_items/form/controls/` people picker (the merge of "Me" + team members +
   Graph results).
   Screenshot: `ipad_worst_2.png` / `pad_15_people_search_s.png`.

3. **The type chooser opens as a phone bottom sheet from "Add child"/"Add related", not the anchored
   menu** the same chooser uses from the Work `+` on the same window width. It fills 70% of the
   height for two rows.
   Owner: the `showTypeChooser` call site in `lib/features/work_items/work_item_detail_page.dart`
   (it is not passing the anchored/tablet variant that `new_work_item_button.dart` uses).
   Screenshot: `ipad_worst_3.png` / `pad_41_addchild_s.png`.

4. **After Create on the tablet the new item does not open.** The dialog closes, the list behind
   refreshes and the item is at the top — but the detail pane still says "Select a work item". On the
   phone the detail page opens. Owner: the `+` completion handler in
   `lib/features/work_items/form/new_work_item_button.dart` (it reloads the list but never selects
   the created id in the two-pane layout). Screenshot: `pad_27_created_s.png`.

5. **Sheet/dialog inconsistency inside the tablet dialog.** Picklists, people and tree pickers all
   open as anchored menus / centered dialogs, but **Tags**, the **State** transition list and the
   **Add attachment** source list open as bottom sheets pinned to the screen edge. The State sheet is
   the worst of the three: its last row ("Active") sits flush against the bottom of the screen with no
   inset and the sheet does not scroll. Owner: `form/controls/tags_control.dart`, the state sheet in
   `work_item_form_body.dart` / `work_item_detail_page.dart`, `attachments_section.dart`.
   Screenshots: `pad_19_tags_s.png`, `pad_30_state_s.png`, `pad_84_add_menu_s.png`.

6. **A reply posted in the file diff is not reflected on the Comments tab** until the user pulls to
   refresh — the two tabs of the same PR keep separate thread state. Owner: the PR detail page's
   shared thread state (`lib/features/pull_requests/`). Screenshots: `pad_117` (stale) vs `pad_119`.

7. **No unsaved-work prompt when leaving a dirty form by the rail.** Tapping Home with a dirty edit
   dialog open switches tab silently (the dialog survives in the branch, so nothing is lost);
   tapping the *current* Work tab does nothing at all. The phone's documented Keep draft / Discard /
   Cancel prompt never appears. Owner: the `UnsavedWork` registry hook in the project shell.
   Screenshots: `pad_34`, `pad_35`, `pad_36`.

8. **The full-screen attachment viewer keeps the glass rail floating over the image**, and the image
   runs under it. Owner: the viewer route in `form/controls/attachments_section.dart` (it should sit
   above the shell, or take the rail's inset). Screenshot: `pad_90_viewer_s.png`.

9. **Cosmetic / low.**
   - The draft row in the anchored chooser truncates to `Resume draft: Task - [io…`; the title and
     age are lost (`pad_69`).
   - The detail page's overflow menu ("Add child" / "Add related") is drawn overlapping the left edge
     of the glass rail (`pad_40`).
   - "Add child" is offered on a Task, which has no child backlog level (`pad_51`).
   - An attachment picked from the library keeps the raw `image_picker_<uuid>.jpg` name (`pad_89`).
   - The state transition list is unordered (New / Removed / Closed / Resolved / Active) (`pad_30`).
   - At xxxL the rail label reads "Pipelin…" and the work list's filter chips clip "Saved query"
     (`pad_157`).
   - `html_editor_enhanced` logs `JavaScript execution returned a result of an unsupported type`
     plus a style map on every editor callback — noisy in the console.

## Behaviour worth recording (not defects)

- **Azure DevOps reactivates a Resolved PR thread when a comment is added.** A plain "Reply" (no
  status call — verified in `thread_card.dart`) left the thread Active, confirmed after a server
  refresh. Suggest adding this to `research/spikes/results/README.md`, and consider whether the
  composer should say so.
- Opening a linked item from the detail page's Links row **pushes a full-screen single-pane work item
  page** rather than selecting it in the two-pane detail pane (`pad_180`). It works — an earlier
  report of "not tappable" was a mis-aimed tap — but it is a tablet inconsistency.
- The anchored (tablet) chooser has no "Other" heading; the non-backlog types just follow a divider.
